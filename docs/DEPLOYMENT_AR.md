# دليل التثبيت والتشغيل التجريبي

## المتطلبات
PHP 8.3 أو أحدث بإضافات OpenSSL, PDO MySQL, mbstring, tokenizer, XML, ctype, fileinfo وComposer 2. MySQL 8.4. خادم Apache أو Nginx يجب أن يشير إلى `public/` لا إلى جذر المشروع. الواجهة لا تحتاج Node أو إنترنت لتحميل ملفاتها.

## قاعدة جديدة منفصلة
أنشئ قاعدة باسم مثل `ibn` بترميز utf8mb4، ومستخدم تطبيق مخصص. على الاستضافة المشتركة استخدم الاسم الكامل الذي ينشئه مزود الاستضافة. لا تعدّل قواعد برامج أخرى.

```sql
-- ينفذه مسؤول قواعد البيانات، لا حساب التطبيق.
CREATE DATABASE ibn CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

استخدم حساب migration ذا صلاحيات إنشاء وتعديل الجداول أثناء النشر فقط. حساب التشغيل ينبغي أن يمتلك الصلاحيات المطلوبة على قاعدة IBN دون صلاحيات عامة على الخادم. امنح جدول التدقيق SELECT/INSERT فقط قدر الإمكان، مع حساب صيانة منفصل. صلاحيات MySQL ومفاتيح التشفير ليست مضبوطة تلقائياً بواسطة هذا المشروع.

## الخطوات
1. `composer install`، ثم نسخ `.env.example` إلى `.env`.
2. ضبط اسم القاعدة ومستخدمها وكلمتها ومضيفها. لا ترسل `.env` في GitHub أو أي مستند عام.
3. `php artisan key:generate` مرة عند الإعداد الجديد؛ ولّد مفتاحاً مستقلاً عبر `php -r 'echo bin2hex(random_bytes(32));'` وضعه في `IDENTITY_HASH_KEY`.
4. `php artisan migrate --force` ثم `php artisan db:seed --force` ثم `php artisan ibn:admin`.
5. اضبط URL وHTTPS وملفات التعريف الآمنة: `APP_DEBUG=false`, `SESSION_SECURE_COOKIE=true` للاستضافة. `false` مقبول فقط للتجربة المحلية على HTTP.
6. `php artisan config:cache` و`php artisan route:cache` و`php artisan view:cache` بعد استكمال المتغيرات.
7. اختبر الدخول وإنشاء حساب بمؤسسة أخرى ومحاولة الوصول المباشر إلى سجلاتها، والتحقق من فشل الوصول.

لا تستخدم `migrate:fresh` أو `db:wipe` على قاعدة تحمل أي بيانات مطلوب الاحتفاظ بها. أوامر الاختبار التي تمسح البيانات تستهدف قاعدة اختبار منفصلة فقط.

## استعادة الوصول
`php artisan ibn:reset-password user@example.com` عبر طرفية الخادم الموثوقة، ثم إدخال كلمة مؤقتة بشكل مخفي. يلزم الموظف بتغييرها وتُحذف جلساته السابقة. لا يوجد endpoint عام لإنشاء المدير أو استعادة كلمة المرور.

## بيانات العرض
`APP_ENV=local` أو `testing` وقاعدة خالية من المؤسسات، ثم `php artisan ibn:demo --confirm`. لا تستخدم بيانات حقيقية. لا تُفعّل demo في خادم Production. جداول السجلات التجريبية ليست مخزون دم حقيقياً.

## التشغيل الحقيقي غير معتمد في v0.1
قبل أي استخدام حقيقي: اعتماد طبي وتنظيمي مكتوب، تحديد الاستضافة وحوكمة البيانات، MFA، تشفير النقل والخزن، نسخ احتياطية مشفرة واختبار استعادة، مراقبة وتنبيهات، إدارة مفاتيح مع فصل المسؤوليات، فحص اختراق، اختبارات حمل وتنافس وحالات انقطاع اتصال. لا يصنع التطبيق هذه الضمانات بمجرد النشر.

الأوقات تخزن UTC وتعرض Asia/Baghdad. إعداد reverse proxy موثوق وTLS للوصول لقاعدة خارجية يحتاج ضبطاً خاصاً بالبنية؛ المثال الافتراضي يفترض قاعدة على مضيف موثوق داخلي.

## النسخ الاحتياطي والمفاتيح
خزّن `APP_KEY` و`IDENTITY_HASH_KEY` منفصلين عن نسخة البيانات مع نسخ احتياطية آمنة. فقدان APP_KEY يمنع فك المعلومات المشفرة. لا تغيّر مفتاح الهوية بلا إعادة فهرسة محكومة. يجب تصميم واختبار تدوير المفاتيح واستعادة النسخ قبل استقبال بيانات حقيقية؛ لم تنفذ أدوات تدوير تلقائية بعد.
