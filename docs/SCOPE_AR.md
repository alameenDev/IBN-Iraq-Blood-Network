# نطاق الإصدار 0.1

## منفذ في الكود
واجهات عربية: الدخول، لوحة المتابعة، دليل الجهات وإنشاؤها وتعديلها، الربط والمراجعة، المستخدمون، الأدوار، طلبات الدم وتفاصيلها ومراجعتها، تسجيل المتبرع وملفه وزياراته، سجل التدقيق، خريطة مراحل النظام، وتغيير كلمة المرور.

الحالات منفصلة:
- المؤسسة: pending → active / suspended.
- الربط: pending → active / rejected؛ active → suspended؛ إعادة طلب بعد الرفض أو الإيقاف يعيده pending مع سجل تدقيق.
- طلب الدم: submitted → accepted / rejected، ويمكن للمستشفى إلغاء submitted أو accepted؛ لا توجد fulfilled أو transfused.
- الزيارة: awaiting_screening → cancelled فقط في هذه النسخة؛ لا انتقال إلى سحب.

كل تعديل حساس يخضع لصلاحية من الخادم، ونطاق مؤسسة، وتحقق مدخلات، وسجل تدقيق. التبعية الإدارية والملكية لا توسعان نطاق بيانات المستخدم تلقائياً.

## ليس منفذاً
اختيار المتبرع طبياً، سجل تأجيل موحد بين المصارف، جمع الدم والعينات، معدات وأكياس ومخازن المستلزمات، الفحوصات وQC، نتائج الأجهزة، فصل المكونات والنسب، المنتج والملصق ISBT 128، الخزن والصلاحية وFEFO، تخصيص الوحدات، الإفراج، النقل والحرارة، المطابقة والصرف، bedside verification، التفاعلات والاستدعاء والإتلاف، المالية والمخاطبات التنظيمية. لا يجوز تفسير قبول الطلب على أنه إنجاز لأي من هذه المراحل.

معرفات DON/VIS/REQ هي معرفات إدارية باستخدام ULID، وليست DIN أو ملصقات ISBT 128. إنشاء أكياس أو استخدام معرفات الزيارات على منتجات دم غير مدعوم.

## الربط مع المستشفيات
منفذ: إنشاء الجهة وحساباتها وطلب ارتباطها بمصرف، وبعد الموافقة طلب الدم ضمن المنصة.
غير منفذ: API خارجي، HIS/EHR، HL7/FHIR/ASTM، اتصال رسمي بالوزارة، IoT أو تطبيق نقل مستقل. هذه تكاملات لاحقة تحتاج موافقات واختبارات ومفاتيح مستقلة.

## لغة الواجهة
العربية RTL هي المنفذة. المصطلحات والأكواد التقنية باللغة الإنجليزية حيث يلزم. لا يوجد زر تبديل إنجليزي شكلي ولا ادعاء اكتمال نسخة ثنائية اللغة.
