# IBN — Iraq Blood Network

نواة الشبكة العراقية لمصارف الدم والمستشفيات · **Administrative pilot v0.1.0**

> **ليست نسخة تشغيل سريري.** لا تدخل بيانات مرضى أو متبرعين حقيقية، ولا تستخدم هذه النسخة لتحديد الأهلية أو المطابقة أو الإفراج عن الدم أو صرفه. الموافقة الإدارية على الطلب ليست موافقة طبية.

## ما هو منفذ؟

- واجهة عربية RTL متجاوبة للحاسبة والهاتف، دون CDN أو حزم JavaScript خارجية.
- دخول بحسابات خاصة، تحديد معدل محاولات الدخول، تغيير إلزامي لكلمة المرور المؤقتة، وإلغاء الجلسات عند تغيير الصلاحيات أو إيقاف الحساب.
- إنشاء مؤسسات: مصرف رئيسي، مصرف فرعي، مستشفى، مركز تبرع؛ الملكية، المحافظة، التبعية، مرجع الموافقة وحالة التفعيل.
- طلب ربط مصرف بمستشفى، اعتماد الطرف المقابل أو مدير آخر بالشبكة، رفض/إيقاف/إعادة طلب الربط. لا يعتمد منشئ الطلب طلبه بنفسه.
- إدارة الحسابات ضمن المؤسسة؛ أدوار نظامية وأدوار محلية مخصصة؛ منع منح صلاحيات أعلى مما يمتلكه المدير المحلي.
- إنشاء طلب دم مرتبط برابط فعال، مراجعة إدارية من المصرف، إلغاء من المستشفى، وسجل تغييرات. **لا حجز أكياس ولا صرف.**
- تسجيل متبرع، تشفير معلوماته التعريفية، البحث بالهوية المطابقة أو رقم السجل، موافقة تسجيل وفتح/إلغاء زيارة بانتظار التقييم.
- عزل سجلات المتبرعين حسب المؤسسة؛ مدير الشبكة لا يحصل تلقائياً على وصول لملفات المتبرعين.
- سجل تدقيق إداري وقراءة السجلات الحساسة؛ اختبارات صلاحيات وعزل وطلبات وواجهة متصفح.

## التقنية

PHP **8.3+** (بيئة الاختبار PHP 8.4)، Laravel **13**، MySQL **8.4 / InnoDB / utf8mb4**، Blade وCSS/JavaScript محلي. قاعدة البيانات الفعلية MySQL؛ SQLite خيار للاختبارات السريعة فقط. لا يحتاج العرض إلى npm build.

## التثبيت المحلي / بيئة Staging مستقلة

```bash
cp .env.example .env
composer install
php artisan key:generate
# ولّد قيمة مستقلة وضعها في IDENTITY_HASH_KEY داخل .env:
php -r 'echo bin2hex(random_bytes(32)), PHP_EOL;'
```

أنشئ قاعدة MySQL جديدة مخصصة للمشروع ومستخدم قاعدة منفصلاً. حدّث `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD`, `DB_HOST` داخل `.env`. لا تستخدم قاعدة مشروع المختبر أو أي نظام قائم.

```bash
php artisan migrate --force
php artisan db:seed --force
php artisan ibn:admin
php artisan serve
```

افتح `http://127.0.0.1:8000`. أمر `ibn:admin` يسأل عن الاسم والبريد وكلمة المرور دون طباعة كلمة المرور. **لا يوجد حساب أو كلمة مرور افتراضية.** `db:seed` ينشئ الأدوار والصلاحيات فقط، ولا ينشئ مستخدمين.

إضافة بيانات مصطنعة إلى قاعدة تجريبية فارغة فقط، بعد إنشاء المدير:

```bash
php artisan ibn:demo --confirm
```

الأمر يرفض بيئة production وأي قاعدة تحتوي مؤسسات مسجلة. لا ينشئ كلمات مرور لحسابات الموظفين. أسماء الجهات التجريبية موسومة بكلمة «تجريبي» ولا تمثل جهات حقيقية.

### الاستضافة

اضبط Document Root على مجلد `public` فقط. في بيئة Staging عبر HTTPS، استخدم `APP_DEBUG=false`, `APP_URL=https://...`, `SESSION_SECURE_COOKIE=true`. أعط صلاحية كتابة فقط للمجلدات `storage` و`bootstrap/cache` حسب مستخدم PHP. راجع [دليل النشر](docs/DEPLOYMENT_AR.md)؛ لا يوجد نشر تلقائي إلى استضافة المستخدم في هذا المستودع.

## تجربة المسار الإداري

1. أنشئ مصرفاً رئيسياً ومستشفى. سجل مرجع الموافقة الإدارية ثم فعلهما.
2. أنشئ مدير مصرف ومدير مستشفى. سلّم كلمات المرور المؤقتة بقناة آمنة، وكل مستخدم يغيرها عند أول دخول.
3. مدير المستشفى يطلب الربط بالمصرف؛ مدير المصرف أو مدير شبكة آخر يعتمد الطلب.
4. المستشفى ينشئ طلب دم. المصرف يقبله إدارياً أو يرفضه. لا ينشئ هذا الإجراء مخزوناً أو توافقاً طبياً.
5. لإضافة متبرع تجريبي: فعّل قدرة تسجيل المتبرعين في المصرف، واستخدم حساب مدير المصرف أو موظف التسجيل. الزيارة تبقى بانتظار التقييم؛ لا توجد خطوة سحب في v0.1.

## الاختبارات

```bash
# SQLite للاختبار السريع، في بيئة اختبار فقط
vendor/bin/phpunit
# MySQL: قاعدة منفصلة قابلة للحذف؛ RefreshDatabase يمسح جداول الاختبار
DB_CONNECTION=mysql DB_DATABASE=ibn_test DB_USERNAME=ibn_test DB_PASSWORD='...' vendor/bin/phpunit
php artisan view:cache
php artisan route:cache
composer audit
```

GitHub Actions معد لتشغيل اختبارات التكامل على MySQL 8.4 وفحص Blade والمسارات، ثم اختبار دخول فعلي وإنشاء مؤسسة بواسطة Playwright والتقاط شاشات سطح المكتب والهاتف. الشارات/نتائج Actions هي مرجع نجاح التنفيذ، وليست هذه الفقرة ادعاء بأن الاختبارات اجتازت التنفيذ قبل تشغيلها.

ملف `composer.lock` يجب تثبيته بعد أول حل اعتماديات ناجح في بيئة متصلة. لا تحدّث الحزم مباشرة في بيئة التشغيل. الاختبارات لا تغني عن اختبار ضغط أو اختبارات تنافس حقيقية متعددة العمليات أو تدقيق اختراق مستقل.

## الحدود والمراحل التالية

الفحوصات والسحب والأكياس وISBT 128 وفصل المكونات والإفراج الطبي والمخزون وسلسلة التبريد والشحن والمطابقة وإعطاء الدم والاستدعاء **ليست منفذة** في v0.1. كذلك لا توجد تكاملات أجهزة/وزارة، أو خدمة SMS/بريد، أو MFA، أو تحقق خارجي من التراخيص. «الربط» في هذه المرحلة هو ارتباط الجهات وحساباتها داخل المنصة، وليس ربط HIS خارجي عبر API.

انظر [نطاق التنفيذ](docs/SCOPE_AR.md)، [قاعدة البيانات](docs/DATABASE.md)، [الصلاحيات والأمان](docs/SECURITY.md)، و[ملاحظات التحقق](docs/VERIFICATION.md).

المستودع عام: يمنع رفع `.env` أو النسخ الاحتياطية أو بيانات الهوية والمرضى أو كلمات مرور حقيقية.
